# Internal mail routing foundation

14 October 2026. Migration4744 implements tenant-scoped aliases and internal forwarding. Source addresses belong to verified active tenant domains; destinations are UUID-selected active same-tenant mailboxes, never arbitrary external addresses or alias chains. Alias has one destination; forwarding supports up to10. Domains retain at most20 route claims, including disabled entries. Source/mailbox collisions are rejected in both directions under the organization transaction lock; disabled names remain reserved until a future retention/purge policy.

Every change commits a complete immutable domain snapshot, generation, request and audit. A separate explicit local worker claims leases, supersedes older generations, retries bounded failures and fences acknowledgements. Default disabled domains cannot reach a provider. The isolated agent independently derives domain ownership from trusted bindings, rejects wrong tenant/source/destination/loops/account collisions, preserves unrelated aliases and durably fences generations before atomic configuration effects. Owned source history allows replay to repair interrupted removal. Effective Postfix texthash lookups must converge stably; configured intent alone is not success.

API: tenant-scoped GET/PUT `/api/organizations/:orgId/mail-routes`. UI shows internal-only routing, editable alias/forward intent and retained disabling. Explicit worker requires test environment and `--lab`; ordinary worker/provider activation is unchanged. Cross-tenant and malformed destination input is rejected; public external forwarding and catch-all are not enabled.

Executed real isolated conformance: alias intent/application, actual Postfix map, SMTP alias delivery to IMAP, internal forwarding to two independently authenticated IMAP mailboxes, remote stale generation rejection, cross-tenant rejection and disabling/removal while preserving address/data. Run `node infrastructure/mail-lab/run-webmail.mjs routing` after building backend/lab worker. Only fixed synthetic pilot/partial credentials are piped through stdin; no plaintext in argv, env, files or results. Messages and volumes are preserved. Unit tests additionally prove collision concurrency, tenant isolation, unknown destinations, duplicate targets, supersession and disabled-address reservation. UI/full-regression results are recorded in the progress ledger when completed.

Remaining: approved external forwarding/SRS/abuse policy, catch-all, route history/pagination, independent mail-node assignment, delivery/DSN observability, provider migration, retention-aware source release, failed-job operations and restart/fault/load expansion.
