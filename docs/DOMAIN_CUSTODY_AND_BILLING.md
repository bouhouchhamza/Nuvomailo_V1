# Domain custody and captured entitlements

14 October 2026. Safe local implementation; no DNS changes, real payment provider or active mail ownership transfer.

Migrations4745–4746 add a sticky domain mail-custody marker. Activation sets it on insert/update and later updates cannot clear it. Existing domains are conservatively marked because historical non-activation cannot be proved. Empty-domain transfer requires a verified identity, password reauthentication and ownership of both active organizations, locks organizations in stable order, enforces target entitlements and rejects any mailbox, retained route, routing generation or mail activation history. It rotates the TXT challenge, requires fresh verification, keeps mail disabled and audits both organizations. Active mail migration/transfer remains blocked pending a separate custody protocol; changing a database owner never moves mail.

The owner dashboard offers only explicitly eligible empty domains and owned target organizations. Unknown/activated domains are not offered. Unit tests prove owner/password checks, fresh proof, sticky custody on update and initial activation insertion. Full suite before the billing follow-up passed24 backend/26 frontend, builds/typechecks.

Migrations4747–4748 capture resource limits with plan identifier/catalog version in subscription and checkout snapshots. Plan edits increment a catalog version. Signed successful sandbox checkout applies its frozen snapshot; later catalog changes cannot change an issued quote or existing subscription limits. Native checks bind snapshots to their plan/version, checkout snapshots/prices are immutable and malformed entitlement JSON fails closed. Existing rows capture their current local catalog state; production rollout cannot reconstruct undocumented historical contracts and needs reviewed backfill.

The first snapshot test found an ambiguity when changing between plans with identical limits/version numbers. Binding snapshots to plan identifier/version corrected it. Billing tests now prove catalog price/quota changes do not mutate a prior quote/subscription, direct quote mutation is rejected and frozen quota enforcement still works. Staff UI describes new catalog versions rather than immediate changes to existing subscribers. Real merchant/tax integration, usage metering, renewal policy and approved commercial migration remain open.
